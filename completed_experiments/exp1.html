EXPERIMENT - 1

Simulation of Hard, Soft, and Firm Real-Time Tasks using Python

Aim / Objective

To design and simulate hard, soft, and firm real-time tasks in Python, analyse their execution behaviour, and evaluate deadline satisfaction in autonomous and embedded systems.

Description

Real-time tasks are classified by the consequence of missing a deadline. Hard tasks must meet deadlines because failure can create unsafe behaviour. Firm tasks may finish late, but late results are discarded. Soft tasks can still be useful after a deadline, with reduced quality.

Pre-Requisites

  1. Python 3.x with a code editor or Jupyter notebook.
  2. Knowledge of release time, execution time, period, and deadline.
  3. Basic Python lists, dictionaries, loops, and functions.

Pre-Lab Questions and Answers

1. Define hard, soft, and firm real-time tasks and give one autonomous-system example of each.
Hard: a missed deadline is unacceptable, such as emergency braking. Soft: late output is degraded but still useful, such as a dashboard status stream. Firm: late output has no value, such as a stale object-detection frame.

2. What is the difference between execution time (WCET) and a deadline?
Execution time is the processor time needed to complete the task. A deadline is the latest acceptable completion time after release.

3. How would you represent a task's timing parameters as a Python data structure?
A dictionary or dataclass can store name, task class, release time, execution time, period, and deadline.

4. What does deadline satisfaction ratio mean?
Deadline satisfaction ratio = number of jobs completed before deadline / total jobs.

5. Why can a firm real-time result be discarded even though it eventually completes?
Because the result describes a past system state and no longer supports the current control decision.

In-Lab

Hands-on simulation of hard, soft, and firm real-time tasks and measurement of deadline satisfaction in Python.

Procedure / Program and Execution

  1. Create a list of real-time jobs with release time, execution time, relative deadline, and task class.
  2. Run a simple non-preemptive scheduler that executes each ready job in sequence.
  3. Compute absolute deadline as release time plus relative deadline.
  4. Mark each job as met or missed.
  5. Compute deadline-miss ratio and compare hard, firm, and soft task behaviour.
tasks = [
    {"name": "Brake actuator command", "class": "Hard", "release": 0, "exec": 6, "deadline": 8},
    {"name": "Collision-warning fusion", "class": "Hard", "release": 2, "exec": 5, "deadline": 12},
    {"name": "Trajectory replanning", "class": "Firm", "release": 4, "exec": 9, "deadline": 14},
    {"name": "HD map refresh", "class": "Firm", "release": 7, "exec": 12, "deadline": 18},
    {"name": "Cabin telemetry update", "class": "Soft", "release": 8, "exec": 15, "deadline": 20},
    {"name": "Video status stream", "class": "Soft", "release": 10, "exec": 18, "deadline": 22},
]

clock = 0
results = []
for task in tasks:
    start = max(clock, task["release"])
    finish = start + task["exec"]
    absolute_deadline = task["release"] + task["deadline"]
    met = finish <= absolute_deadline
    results.append((task["name"], task["class"], start, finish, absolute_deadline, met))
    clock = finish

met_count = sum(1 for row in results if row[-1])
miss_ratio = (len(results) - met_count) / len(results)
for row in results:
    print(row)
print("deadline miss ratio =", round(miss_ratio, 2))

Analysis and Inferences

  • The two hard tasks meet deadlines in this run, so safety-critical outputs are delivered before they expire.
  • The firm tasks begin missing deadlines as queued work increases; their late results must be discarded.
  • The soft tasks also miss deadlines, but the results can still be used with reduced quality.
  • Deadline classification changes the interpretation of the same timing miss: unsafe for hard tasks, useless for firm tasks, and degraded for soft tasks.

Viva-Voce Questions and Answers

1. What consequence distinguishes a hard deadline miss from a soft deadline miss?
A hard deadline miss can cause system failure or unsafe behaviour; a soft miss mainly reduces service quality.

2. How did your simulation detect that a deadline was missed?
It compared each job's finish time with its absolute deadline.

3. What Python constructs did you use to model task execution time?
Dictionaries stored task parameters, and loops simulated sequential execution.

4. How would increasing task execution time affect the deadline-miss ratio?
It increases processor demand and generally increases the miss ratio.

5. In an autonomous vehicle, which subsystems require hard real-time guarantees?
Emergency braking, stability control, steering actuation, and collision avoidance need hard guarantees because delay can directly affect safety.

Post-Lab Questions and Answers

1. Extend your simulation to run 100 randomly generated tasks with mixed timing classes; compute and plot the deadline-miss ratio for each class as system load increases from 40% to 120%. Interpret where each class begins to fail.

import random

def run_trial(load, seed=341401):
    rng = random.Random(seed)
    factors = {"Hard": 1.75, "Firm": 1.35, "Soft": 1.25}
    counts = {"Hard": 0, "Firm": 0, "Soft": 0}
    misses = {"Hard": 0, "Firm": 0, "Soft": 0}
    useful = {"Hard": 0.0, "Firm": 0.0, "Soft": 0.0}

    for i in range(100):
        task_class = ["Hard", "Firm", "Soft"][i % 3]
        base_exec = rng.uniform(4.0, 18.0)
        actual_exec = base_exec * load * rng.uniform(0.90, 1.35)
        deadline = base_exec * factors[task_class]
        met = actual_exec <= deadline
        counts[task_class] += 1
        misses[task_class] += 0 if met else 1
        if met:
            useful[task_class] += 1.0
        elif task_class == "Soft":
            useful[task_class] += 0.55

    return {
        cls: (misses[cls] / counts[cls], useful[cls] / counts[cls])
        for cls in counts
    }

for load in [0.40, 0.60, 0.80, 1.00, 1.20]:
    print(load, run_trial(load))
